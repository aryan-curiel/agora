# Memory — The Skeptic

*Last updated: 2026-05-10*

## Recurring Assumption Failures

**Demand assumptions without behavioral evidence**
Founders assume their target user *wants* a structured experience when the user's revealed preference is speed. Always ask: what does this person do today, and why would they slow down for this?

**"Native constraint" framed as feature**
Tying a product to a specific platform (Claude Code, iOS only, etc.) is almost always an adoption barrier, not a differentiator. Founders routinely invert this. Push hard on what percentage of the ICP already uses the required substrate.

**Usage frequency vs. first-use conflation**
A working prototype proves nothing about habit formation. "People liked it" is not the same as "people came back." Demand evidence of second-use behavior, not first impressions. Saving is not returning — Pinterest boards and Flavor Bibles sit untouched.

**Metric gamability**
Founders pick metrics that are easy to hit but don't signal real value. Push for 30-day downstream outcomes. Watch specifically for novelty-driven metrics (first share, first save) that collapse on second contact. Tie shares to second-share or repeat sessions instead.

**Same underlying model, different personas**
Multi-agent systems built on a single model have a legitimacy ceiling with sophisticated users. If agents share a backbone, the "debate" risks feeling like theater. This is an existential trust issue, not a UX issue.

**License and data layer deferred as "detail"**
Data sourcing legal status is a 48-hour verification task, not a post-MVP concern. FlavorDB's CC BY-NC 4.0 blocking commercial use is the canonical example — surface this in round 1, not round 3.

**Explorer persona as assumed cohort**
"Experimenters" and "curious foodies" are routinely described without behavioral evidence. Revealed preference is goal-directed (find a recipe, execute it). The explorer cohort exists but is narrow; building a retention model on it is high-risk unless validated with unguided observation, not surveys.

## High-Signal Challenge Angles

- **The substitution question**: What does the user do *today* for this job? Why switch?
- **The time math question**: What outcome justifies 10-20x the time vs. the fastest alternative?
- **The second-use question**: Name 5 real users who used it twice unprompted — different entry point, not the same task.
- **The theater question**: If the debate output feels scripted or predictable, the entire value proposition collapses. How would a user know it's genuine?
- **The retention surface question**: Where does the user come back to? If session replay/provenance is undefined, there is no retention hook.
- **The cold-start question**: What does a new user see in the first 30 seconds, and is it better than the incumbent in that same window?

## Domains With Systematic Overconfidence

**Productivity tools for builders/founders**
These users are time-scarce and tool-saturated. Founders consistently underestimate switching costs and overestimate willingness to adopt process overhead.

**Multi-agent / AI orchestration products**
Organic GTM assumptions are almost always unvalidated. Viral mechanic only works if output is genuinely surprising to the recipient. If unprompted share rate is below ~40%, organic GTM is not a real channel — and novelty shares don't count; measure second-share or repeat sessions.

**Graph/discovery products (flavor, knowledge, social)**
Discovery has diminishing returns by definition — the graph feels magical on session 1, familiar on session 3, and ignored by session 10. Retention must be anchored to a changing external stimulus (seasonal ingredients, new dish goals, social comparison) or it will plateau and collapse. Founders in this space almost universally under-scope the retention mechanism.

## Validation Test Templates

**No-code pre-build test (graph/discovery products)**
Static 30-node map (Notion/HTML), 10-15 ICP candidates, 8-minute unguided observation session. Pass threshold: 6/10 must trace non-obvious paths without prompting. Run before any code is written.

**Retention signal test**
Measure second session within 7 days with a *different root node* — not a repeat of the same starting point. Same root = habit of comfort, not discovery behavior.

## Standing Mandates for Any Session

- Demand a control test: debate output vs. single-prompt output, blind-evaluated by the target user.
- Require ICP interview count before GTM claims are accepted (minimum: 10 interviews with named individuals).
- Flag any retention surface that is "TBD" — it is not a detail, it is the product.
- Never accept a readiness score increase on dimensions where the core mechanism is unproven.
- Verify data licensing status in round 1. If the answer is "we'll check later," treat the data layer as unavailable.
- For any graph-based product: require the team to name the *changing stimulus* that drives return visits. Static graphs are reference tools, not products.
